# Evidence-Linked Operator Review Panel

## Purpose

An evidence-linked operator review panel was added to strengthen the operational decision-support layer of the risk-aware inspection prototype. The purpose of this update is to connect each selected inspection record with the visual artefacts generated by the anomaly detection and localisation stages.

This ensures that operator review decisions are not made from tabular metadata alone. Instead, the operator can inspect the anomaly evidence visually before confirming whether a case should be released, rejected, reinspected or escalated.

## Implementation

The NiceGUI dashboard was extended so that, when an inspection record is loaded, the system searches the local `outputs/` directory for visual artefacts matching the selected record's image identifier. The dashboard then displays the available evidence directly in the operator review interface.

The displayed evidence may include:

* annotated inspection evidence;
* heatmap overlay evidence;
* predicted mask evidence;
* anomaly-map evidence.

The evidence search is linked primarily through the `image_id` stored in the PostgreSQL `inspection_records` table. Matching artefacts are served from the local outputs directory using NiceGUI static file serving. Duplicate-looking artefacts are filtered so that the dashboard presents a cleaner review panel.

## Methodological relevance

This update improves the traceability of the inspection workflow. The review process now links four important components:

1. the inspection record stored in PostgreSQL;
2. the anomaly detection and localisation output;
3. the visual evidence shown to the operator;
4. the operator review decision saved back into the audit database.

This supports the dissertation aim of developing a risk-aware inspection pipeline rather than a standalone anomaly detection model. It demonstrates how model outputs can be converted into practical operator-facing evidence for quality-control decision support.

## Operational value

The evidence-linked panel is particularly useful for false-positive handling. If an item is flagged as anomalous but the visual evidence suggests that the detection is not operationally meaningful, the operator can record a false-positive release decision. The QA disposition logic can then use this review decision to release the item after review.

This reflects a realistic industrial inspection scenario where automated anomaly detection is combined with human judgement for uncertain or high-risk cases.

## Scope

The current implementation is a prototype-level evidence display layer. It does not control physical production-line equipment or automatically actuate a reject gate. Instead, it demonstrates the software-side decision-support logic that could later be connected to a manufacturing execution system, programmable logic controller or robotic sorting mechanism after further validation.
